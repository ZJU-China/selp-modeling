# Engineering —— 分子动力学平台的工程设计（DBTL）

> **页面定位**：本页用 **Design–Build–Test–Learn（DBTL）** 循环记录本条 iGEM 项目
> 中「软件与计算平台」的工程设计过程。只保留**框架级的大改动**：平台从「单任务监控」
> 走向「参数驱动的流水线」的每一步动机、取舍与验证，技术细节与 bug 修复从略。
>
> 时间线与实现依据见本仓库的 git 提交记录；使用方式见 *Software / Flow Console* 页面。

---

## 概述

SELP 水凝胶的研究依赖一条跨软件的分子模拟链路：**全原子 TIGER2（NAMD）→ 粗粒化 CG
（GROMACS）→ 磁力学复合模量（MATLAB）**。让这条链路"可看、可调、可重跑"，本身就是
一个工程问题，我们按 DBTL 循环来推进。

总体上我们经历了四个框架级阶段：

| 阶段 | 时间 | 框架级成果 |
|---|---|---|
| **Cycle 0** | 2026-07 | 首个可用的单任务监控平台 |
| **Cycle 1** | 2026-08 | 任务类型插件化 + 流水线（Flow）串联 |
| **Cycle 2** | 2026-09 | 从序列到性质的完整计算链（CG + 磁力学） |
| **Cycle 3** | 2026-10 | Flow Console：参数驱动的交互式平台 |

每个循环内部的 **Learn** 都直接促成下一个循环的 **Design**，因此这四个阶段是有因果链条的，
而不是四个并列的功能堆叠。

## Cycle 0：从"没有平台"到"看得见模拟"（2026-07）

### Design

- 团队在 iGEM 与浙大集群上运行 NAMD TIGER2 副本交换模拟，此前进展只能靠 SSH 一条条命令
  去 grep 日志，无法判断"跑到哪了"。
- 设计目标：一个 Web 界面，能跨 SSH 展示远程任务的关键状态（进度、温度、收敛），
  而不是一个人在终端里盯日志。

### Build

- 搭建前后端脚手架：Express 后端 + Vite/React 前端。
- 引入 TIGER2 任务类型，接入 iGEM 本地服务器（SSH 拉取状态），实现任务监控 UI。

### Test

- 在真实 TIGER2 任务上验证：日志前缀（logPrefix）、副本数量识别、进度显示
  （`d0e625f` 起）；随后补上收敛检测与进度同步（`1f9ac9f`、`487864b`）。

### Learn

- 监控代码与**具体的任务类型强耦合**：每加一种模拟软件就要改一整套监控逻辑。
- 新需求已经出现：GROMACS CG 也要被监控；轨迹（DCD/轨迹文件）大家希望直接在浏览器里看。
- ⟶ **结论：任务类型必须"插件化"，监控逻辑必须按任务自我描述。**

## Cycle 1：任务类型插件化 + 流水线串联（2026-08）

### Design

- 把"跑在哪个服务器、用什么检测、产出什么"下沉到每个任务类型自己的 `main.py` 中，
  让后端按类型分发，而不是写死 TIGER2。
- 先解决"看得见"：多段 DCD 合并的轨迹查看器、序列标注、服务端 MP4/GIF 渲染
  （`dce0d8b`、`c50dc40`）。
- 再解决"串得起来"：任务之间用 **next 链接**传递产物（output → 下游 input），
  引入**转换任务**（TIGER2 轨迹 → CG 起点结构）作为衔接（`106f76f`、`de59299`）。

### Build

- 重构出**任务类型插件化**体系：`backend/tasktype/<type>/`，SSH 路由改为逐类型的
  `main.py` 分发（`7505020`、`d72ab16`）。
- 新增 gromacs_cg 任务类型 + 轨迹可视化 UI（`d618a9c`、`eebacd4`）。
- 实现 **Flow 流水线**：自动顺序启动整条链 + 转换任务生成器（`9e39fb8`、`bb61fde`）。
- 合并共享 Python 模块到 `_shared/`，加入"运行中任务"栏；平台更名为 Molecular Dynamics
  Platform（`1ccc667`、`17fa53e`、`391f7fc`）。

### Test

- 用一条真实的全流程（2KY-10: TIGER2 → 转换 → CG）端到端验证：一键顺序启动、
  产物自动传递（`069b208`、`b88725a`）。

### Learn

- 流水线把"手工传文件"变成了"自动传递"，但**科学参数仍然散落在配置文件里**：
  改一个数要 SSH 进服务器改文件，改完还可能"结果没变"却说不清为什么。
- 模拟运行中出现"跑挂了没发现、等了几小时"的情况，也需要有人值守。
- ⟶ **结论：下一阶段要做两件事——可编辑参数（把参数变成面板字段），以及自动化值守。**

## Cycle 2：从序列到性质的完整计算链（2026-09）

### Design

- 团队研究目标明确后，平台需要承载一条 **序列 → 结构 → 粗粒化 → 杨氏模量 → 磁力学响应**
  的完整性质计算链，而不仅是"监控别人的模拟"。
- 设计要点：
  1. 新增 **AA→CG 粗粒化管线** 与编排脚本（autopilot），把序列一键算到网络模量；
  2. 新增 **magnetomech** 磁力学任务类型：读 CG 模量 → 算外加磁场下的形变；
  3. 每条链的尾端自动追加 magnetomech 步骤（`9f74c4c`、`51adc5c`、`4f7e47d`）。

### Build

- CG 侧：AA→CG 映射 + 32 链候选生成 + 橡胶/力平衡分析（`1ca1bb0`、`1ced5f9`）。
- 交联位点 UI 与序列契约测试（`4b56703`）。
- 磁力学侧：CG 模量 → 场致形变计算 + 任务类型 + 本地计算接口 + MATLAB 3D 图渲染
  （`fcbe6e8`、`68d975e`、后续 magnetomech-dashboard 系列提交）。

### Test

- 对六张 MATLAB 场量图（模量、位移场、轴向应变、孔隙压力、轴向应力、外加磁场）逐张
  校验布局、标注与坐标轴（磁感应强度 B(z) 与磁化强度 M(z) 分轴绘制等，
  `17e323e`～`49839c9` 一系列修图提交）。

### Learn

- 计算链"能算出来、能画出图"，但**每个步骤的参数（序列、交联、体积分数、磁场剖面）仍要靠
  改配置**，与"监控平台"时代的体验没有本质区别。
- 图形叙事变好看了（场量图替换纯轨迹图），但不解决"让用户改参数并重跑"的核心问题。
- ⟶ **结论：必须做 Flow Console——把每个步骤的科学输入变成可编辑表单，参数自上而下传递，
  也就是现在这个平台的主体。**

## Cycle 3：Flow Console —— 参数驱动的交互式平台（2026-10）

### Design

- 一条流水线 = 依次衔接的若干**步骤**（flow_tiger2 / 转换 / flow_gromacs_cg /
  flow_magnetomech），每个步骤拥有：参数面板、运行控制、结果图表。
- 三个框架级设计决策：
  1. **参数驱动而非文件驱动**：面板保存"意图"，任务启动时用参数重新生成输入文件，
     杜绝"改了配置但结果没变"；
  2. **四区块标签页**（Dashboard / Parameters / Results / Control），单页面承载整条链；
  3. **模板创建**：从模板一键生成整条有序、自动串联的流水线（`5b2bd23`）。

### Build

- flow-centric 前端 :5174 + 后端 Flow 读模型（`b1a7b6e`）。
- 四区块改为标签切换（`8f40e9b`、`89ab1d5`）。
- 三个计算步骤全部可编辑：
  - flow_tiger2：序列输入、从已有结构反推序列、motif 标注（`a74d0eb`、`1f14139`）；
  - flow_gromacs_cg：交联 / 温度 / 拉伸输入（`1be6796`）；
  - flow_magnetomech：四相复合体积分数 + 磁场剖面（`d35c16e`、`d2d18b4`）。
- 参数自上而下传递：CLI → 顶层键 → 默认值；占位符永不进入命令（`cddf847`）。
- 运行控制闭环：start/stop/restart/**pause/continue**、Execution 面板（显示真实运行位置与
  工具解析）、GROMACS 应用内启动（SLURM 用 sbatch，无 SLURM 用 setsid 分离启动）
  （`17007a0`、`d78c212`、`cddf847`）。

### Test

- 新增 `test_launch.py` 回归套件（启动、存活检查、完成检测、无 SLURM/sbatch 路径等）。
- 在 iGEM 服务器上做真实端到端冒烟测试：应用内完成 grompp + mdrun，实测 `894 ns/day`，
  确认"快速跑完的冒烟测试算成功、不会被误报成失败"。
- `tsc --noEmit` 与 `vite build` 通过；后端 44 项 Node 测试全绿。

### Learn

- 前端从「单任务监控」最终收敛为「流水线控制台」（删除旧前端，保留 Flow Console）。
- 设计取舍沉淀为文档：参数驱动、立即校验（非法序列/体积分数/字段单位/路径字符集）、
  运行位置用绝对路径子面板、单位必须明确（毫米若当米会得到接近零的磁场）——详见
  *Software* 页面「设计取舍」章节。

## 循环汇总（Cycle Overview）

| 循环 | 时间 | Design 起点 | Build 成果 | Test 验证 | Learn 输出 |
|---|---|---|---|---|---|
| **C0** | 07 | 远程模拟不可见 | 单任务监控平台 | 真实 TIGER2 进度/收敛 | 需要插件化 |
| **C1** | 08 | 多类型任务 + 流水线 | 任务类型插件化、Flow 串联 | 2KY-10 端到端 | 参数需可编辑 + 需值守 |

| **C3** | 10 | 参数驱动交互 | Flow Console 四区块 + 模板 | 回归 + 真实冒烟 | 平台收敛为单一控制台 |

## 设计取舍（由各 Cycle 的 Learn 沉淀而成）

1. **参数驱动，而不是文件驱动。** 代价：重启会重新生成输入；收益：参数与结果永远一致。
2. **只有一个页面，而不是每个任务一个页面。** 代价：信息密度高；收益：整链可见。
3. **立即校验，而不是跑完再报错。** 非法序列、占比超 1、毫米当米、非法路径字符，
   都在点保存的那一瞬间被拦下。
4. **运行位置是部署决策而非物理参数。** 单独成子面板、强制绝对路径、限制 prefix 字符集。
5. **磁力学本地计算，而不是占用集群。** 秒级计算，等待调度反而是浪费。
